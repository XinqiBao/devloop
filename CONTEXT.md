# Repository-Local Context

For projects with a concrete continuity need, I use `.context/` as an agent-neutral, normally untracked place for local working context. It is subordinate to durable tracked project truth. A small project may need none; a larger one may need only a tiny entry point.

When using it, provide a discoverable entry point with a bounded default read path. Keep active state current and check it against the repository and other relevant reality before relying on it. Retire completed work from the active path. Store only the least state that makes work understandable and resumable; do not duplicate tracked facts or turn the directory into a collection of prompts, transcripts, routine reports, or fixed planning forms.

Ignored files are neither secure storage nor a backup. Keep secrets in appropriate secret storage and irreplaceable facts in a durable location. Choose any further structure only when the project's actual retrieval and maintenance needs justify it.
