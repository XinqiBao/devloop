# Commits

Use Conventional Commits by default, grouping each commit around coherent engineering intent. Avoid both unrelated aggregate commits and fragmentation that obscures the change.

Choose branches, pull requests, worktrees, merge style, and commit count according to the task and repository. None is a mandatory workflow for applying this guidance.

Use a commit body when non-obvious rationale helps explain the change. Put enduring project knowledge where future readers will need it; a commit message should not be its only home.
