# Applying devloop

Apply the relevant engineering ideas in the target environment's own terms and locations. Its engineers and agents should be able to use the result without access to this checkout.

## Understand the target

Inspect the target's existing instructions, conventions, tools, and constraints. Identify what guidance is already present, what is missing, and which local requirements govern the change. A parallel set of instructions can conflict with existing ones and make the current guidance harder to find.

Determine whether the task calls for a review, selective application, or broader adoption. Even broad adoption need not copy this repository's structure; it means the relevant guidance works in the target. A review may end with findings only. No change is needed when the target already explains the relevant judgment well.

## Express the guidance

Put missing guidance where its readers already look: an existing project guidance file, native agent configuration, or another appropriate location. For example, add a missing engineering principle to the project guidance file that engineers and agents already consult. Keep provider and tool settings in their native configuration.

Select guidance that fits the target's needs and respects its existing requirements. Reconcile differences when both can be satisfied. If two legitimate requirements conflict, or a choice would materially change the intended behavior, ask the owner to decide. Do not silently override target-specific direction.

## Check the result

Review the result for conflicts, duplication, and references to this checkout. Check links and, where practical, confirm that readers and agents can find and use the guidance.
